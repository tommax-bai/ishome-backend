## 判定：三条实况

1. **原文直取一旦打通，转引源的价值只剩交叉验证**。本轮找到路径 = 住建部公告说明标准在门户网站公开 → 高校/机构镜像托管的标准全文 PDF（GB/T 50034-2024 在 zcsys.ncepu.edu.cn、GB/T 3324-2024 在 fjsec.com）。付费标准库（工标库/国家数字标准馆/规范库）全部只放到目录或前两节；**镜像 PDF 是本项目现阶段唯一可行的原文通道**。GB/T 44309-2024（岩板）与 GB/T 3326-2016（家具尺寸）没找到镜像，即被挡住——这条通道的可得性是随机的，不构成稳定的自动化抓取源。
2. **★ 本轮最大的口径发现：标准给的是"合格底线"，不是"材质属性"**。GB/T 3324-2024 表 4 说的是"任何木家具漆膜都不得低于 3 级"，不是"白橡开放漆的耐磨等级是 3 级"；GB/T 23266-2009 §5.5 说的是"地面用有釉陶瓷板不得低于 3 级/750 转"，不是"这块哑光岩板耐磨 750 转"。把底线填进 attribute 的属性位，形态上像是取到了数据，实质是**用行业下限冒充产品参数**——比数值错误更难发现。故三条材质条目 source 已可定位却仍留 pending、保持 draft。这与规则 4.10b 防伪装是同一类问题的另一个面：那条防的是"纪律伪装成知识"，这条要防的是"底线伪装成属性"。
3. **收纳尺寸库的形态可能是错的**。四条全部卡在同一处：品类名（28寸行李箱/立式吸尘器/扫地机基站）对应的厂商公开尺寸是型号级的，跨型号/跨配置离散度（吸尘器 132mm、基站 243mm）已经大于柜内净空的设计余量。取任一型号点值都不能代表品类，取平均违反禁令。这不是"再多找两个源"能解决的——是 attribute 的值形态问题（点值 vs 区间/包络），需拍板。

## 需要拍板（不替用户裁决）

1. **收纳物品尺寸的值形态**：维持点值（则须定义"取哪个型号/哪种配置"的规则），还是改为区间/包络（则 `attribute_schema` 的 w/d/h 要从 number 改成 [min,max]，并影响下游净空校核的求值口径）？
2. **材质 attribute 是否允许承载"国标底线"**：若允许，需在 schema 里增设字段区分"底线要求"与"实测属性"（例如 `floor_requirement` vs `measured`），否则两类值混在同一属性位上，下游无法判断能不能作判断句背书。本轮按"不允许"处理（留 pending 保持 draft）。
3. **`lkp-cri-living` 的 Ra≥90 定位**：原文核实后它在多数住宅场所是高于国标的**品质主张**（非可核事实），只在化妆台与国标重合。是继续作为选型参数（经验条目性质）保留，还是拆成"国标底线 Ra80（可核）+ 品质档 Ra90（主张）"两条？
