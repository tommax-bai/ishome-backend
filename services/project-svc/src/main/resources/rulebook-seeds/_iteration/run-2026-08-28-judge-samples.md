# 自迭代回路 · 判官反例样本首采 · 2026-08-28

> 性质：规则 4.17 自迭代回路的首次运行（与 `_acquisition/`＝规则 4.16 获取回路并列，两条回路各记各的）。
> 来源裁决：用户 2026-08-28 拍板**反例库不用旧材料（13 轮附录 A 转化作废），改由冷启动真跑样本自建**——
> 规则 4.17 原文即"种子集初版来自冷启动期问题样本"，且同条写明**种子集真实度=系统能发现问题维度的天花板**。
> 纪律：本文所有 `bad` 句**逐字取自真实跑批输出**，无一句润色或重构；**禁止想象填充**（规范 v2.3 §12 禁止项）。

## 一、跑法

15 次 compose 真跑 / 38 次真实 LLM 调用（`report-unit-compose.default` → qwen-plus，temperature=0，与生产同参）。
变量轴：域（lighting ×11 / ergonomics ×3 / budget ×2）× 权益档（PAID 原包 / FREE 全降档 / FREE 保留 calibrated 支点）
× 匿名画像（原画像 / 全空画像 / 矮身高族+一字厨+暗房间 / 高身高族+L 厨+开放阳台）× 重复跑（同输入 ×3 测稳定性）。

**两条基线事实**：

1. **过检率约 1/3**：15 跑中 verdict=ok 仅 3 次。同一输入跑 3 次，attempt-0 输出 sha1 完全一致，但收到同一份机检反馈后 attempt-1 分叉，1 通过 2 失败。成文线是 gen-generated 不要求可重放，但这个基线是观察态门禁定阈值的前提。
2. **三次 ok 的成品，三次全部含语义缺陷**——即"机检全绿 = 内容可发"在真实链路上**一次都没有成立过**。这是判官层存在理由的第一份实证。

## 二、缺陷分类与真样本（按"能不能溜进成品"排序，非纯频次）

### ④ 参考口吻被写成断言 —— 零背书且有产出的跑 2/2 命中，1 次一稿即过

- `bad`（budget，r12 **verdict=ok 成品**）：`拆改、水电、泥木这三项通常构成前期硬装主力，而主材与定制往往占去近半支出。`
- `why`：本轮 `backed_predicates=[]`，prompt 已逐字告知"各分项占比"这轮不许下结论；唯一支点 `lkp-budget-share` 是 REFERENCE_ONLY（draft），按规则 4.10c 只能参考口吻、不得作判断支点。此句以"构成主力""占去近半"下了占比结论，且把区间（主材 [0.20,0.35]+定制 [0.20,0.35]）自行收窄成点值"近半"——**规则 4.10c 禁止的"引擎自己编数字"的对称形态**。造价章另叠加规则 5.15（全章参考级只出区间）。`assertions=[]` 使机检全线放过（规则 4.10c 已写明"没声明就不是断言"机检不保证）。
- `fixed`：`每一项占多少，目前只能给参考区间，区间在表里逐项列。哪一项最后吃掉最多，取决于定制的延米数——这个数还没算出来。`
- 同族（lighting，r07）：`厨房操作台需要比一般活动区域更亮的灯光。` ——主旨句不含 `{lkp-*}` 占位，`gate-thesis-degraded-anchor` 因此完全不触发。

### ③ 断言射程外推 —— 4/15 跑，3 次成品里中了 2 次

- `bad`（lighting，r13 **成品**）：`你家起居室、卧室、走廊、餐厅、厨房一般活动区、卫生间的日常活动区域，灯光显色指数不能低于 {lkp-cri-living}。`
- `why`：该卡 assertions 声明了「显色指数下限」，其唯一支点 `lkp-cri-living` 名称即"**起居空间**显色指数下限"，只背书起居/卧室。把它作为走廊/餐厅/厨房/卫生间的判断句支点＝用一个落点背书它**射程之外**的断言，违规则 5.8 与 4.10a。机检 `gate-assertion-unbacked` 只校验 requires 的 lkp- 是否存在且非降档，**不校验射程**——结构上判不了，判官层专属。
- `fixed`：`你家起居室和卧室的灯光，显色指数不能低于 {lkp-cri-living}。走廊、餐厅、厨房、卫生间另有各自的要求，在选型表里分开列。`

### ① 编造家庭事实 —— 有产出的 12 跑中命中 10 跑

- `bad`（lighting，r13 **成品**）：`比如沙发面料的纹理、孩子的画作、食物的颜色，都会更准确。`
- `why`：匿名画像字段全集只有身高族 + layoutFeatures，**无家庭构成**；"孩子"是无中生有。违规则 4.3（个性化必须锚 triggered_by，"你说过的话变成了图上的东西"是 stage-project 核心信任机制，凭空捏造是它的反面）与图 v0.2 §0（生成侧不知用户是谁）。
- `fixed`：`比如沙发面料的纹理、衣服的颜色、饭菜的成色，在这种光下都更接近本来的样子。`
- 变体：`你平时可能一边在沙发上看书，一边家人在电视墙前活动…`（r07）／`尤其家里有老人或小孩时…`（r15，条件式捏造更隐蔽）／`孩子在地毯上玩积木`（r04，**全空画像下仍捏造**）。

> **根因（已处置，不进判官库）**：`persona-ergonomics.identity` 原文写着"说'你'和'你太太'"——**persona 自己在教模型编造家庭成员**。已按规则 4.19 改源修正；同批发现 material/storage/softdeco 三个 persona 预设了输入未必存在的采集答案（"你说不想费心保养这句话要回响""盘点数字要出现在结论里"），同属诱导编造，一并加条件限定。lighting persona 无此句而"孩子"仍在 10 跑中出现，说明**另有自发捏造**，故判据仍需建。

### ② 自证式依据宣称 —— 有产出的 12 跑中命中 8 跑

- `bad`（lighting，r08 **成品**）：`这个倍数不是凭感觉定的，是根据人眼对明暗对比的实际响应确定的。`
- `why`：`lkp-accent-ratio` 的背书是过了可核性门的国标条文，不是"人眼对明暗对比的实际响应"这一自造机理。属规则 1.6 明文禁止的伪专业形态（空泛概念叙事＋无计算依据的术语堆砌）。机检 `cr-methodology-language` 收的是"依据|推导|验收标准|本方案|经严谨|综合考量"字面，**模型已演化出整套绕开词表的同义变体**。
- `fixed`：删掉自我背书，只留结论与生活后果。
- **最恶劣变体**（r05）：`这个倍数范围是根据大量家庭使用反馈定下的…` ——违规则 4.18（首份报告发出前系统内零行为信号，该事实不存在）与规则 4.17（品味验证只能是转化与行为信号）的反面：**模型伪造了信号来源**。不是措辞问题，是虚构系统能力。
- 其余同族真句：`这个'亮多少'是有依据的，不是凭感觉定的。`／`九十是一个经过验证的下限值`／`这个范围是经过实际使用验证的舒适区间`／`这个亮度关系不是随便定的，是按实际使用需求确定的。`（成品）

### ⑥ 让读者做他做不了的事 —— 4/15 跑

- `bad`（lighting，r07）：`各项参考值目前只作区间提示，实际安装时建议先试装一两盏，看看是否合你习惯。`
- `why`：让业主自费买灯试装做实验——他做不了、也不该被要求做。违规则 1.3（产物必须映射到业主四类动作之一，"试装看看"不属任何一类）；图 v0.2 §5 读者代理第三问"哪句在让我做事"直接命中；与规则 4.18 冲突——没依据就该缺席，不该把不确定性转嫁给业主。
- 同族：`你可以在镜子上方或两侧安装灯具…`／`要在切菜、炒菜的位置加装向下打光的射灯` ——施工指令口吻，与规则 3.5/2.2"不构成施工指令"相抵。

### ⑤ 弱词漏网变体 —— 5/15 跑

- `bad`（lighting，r07）：`你可以考虑在吊柜下方加装灯带或射灯…`
- `why`：违规则 5.9。机检禁词表收的是"可能|建议考虑|也许|宜|尽量|视情况"，"**可以考虑**"只差两字即绕过。
- 实测漏网词面（全部逐字出现且未被任何机检拦下）：**建议先** / **大致是** / **通常** / **往往** / **多数**。两层都要补（词表 + 判官）。

### ⑦ 越权承诺 + "我们"人称 —— 2/15 跑

- `bad`（lighting，r10）：`…实际安装时我们会根据你家层高、墙面颜色和家具深浅微调。`
- `why`：①承诺了系统不提供的服务（报告是参考级产物，不含现场调试）；②人称违 persona 原文"不说'我们建议'"；③"实际安装时我们会…"把责任主体写成施工方，与规则 2.2/3.5 相抵。三个问题机检一个都判不了。

### ⑧ 低频但形态清楚（各 1 跑）

- **编造市场事实**（r09）：`市面上多数普通灯达不到…` ——关于货架在售分布的事实断言，系统内零 attribute 背书（规则 4.9/4.16），冷启动期货架回流为零（规则 4.18）。
- **伪因果·真字段假推导**（r05）：`因为你在一字型厨房里切菜、在封闭生活阳台上晾衣、在没有玄关的入口处换鞋，这些动作都需要更清晰的视觉判断。` ——三个户型特征确实来自画像（合法），但与本卡结论（重点照明倍数）**没有推导关系**。规则 1.5① 要求"推导可见"展示的是真实计算过程，此处把个性化字段当装饰贴上去。**这是"个性化"被伪造的形态：字段是真的，因果是假的，比 ① 更难发现。**
- **空心判断句**（r09）：`…显色指数不能低于一个基本门槛。` ——判断句形式完整但零可带走内容，违规则 1.6 与 5.0b 四件齐（"数据"一件缺席）。成因是模型被数字门禁逼退后把数字整个删掉。
- **模板复读**（r07）：同一稿 5 张卡片正文末句逐字相同——属页级判据（图 v0.2 §4 takeaway / one-thesis-per-page），不宜挂单元级 cr-。

## 四、判不准的（诚实标出，未收录）

1. **区间落点被当标量用**：`至少要是周围环境亮度的 {lkp-accent-ratio} 倍`（值 `{min:3,max:5}`，句式丢掉了 max=5 这个"太亮会刺眼"的上限）。倾向**机检可补**（落点 value 形态 vs 句式"至少/不超过/在…之间"的匹配是确定性的），不该进判官库；但渲染层如何替换区间对象尚无实现可看，故判不准。
2. `下沉式卫生间通常有更强的空间感` ——疑似编造，但找不到可锚的权威口径，**不算数**。
3. **禁词规避是否算伪合规**：lighting 禁词含"照度"，模型全程改用"亮度"绕开。既可能是正确的生活化翻译（persona 本意），也可能是词表规避，**判不准**。
4. **ergonomics 域一条反例也没采到**（3 次全空数组）：该域零 calibrated 直接交白卷，追记三的"你和你太太"**未能复现**。该域样本要等获取回路补上依据后才采得到——**严禁据此想象填充**。

## 五、同批发现的机检层漏洞（这类补 gate，不进判官库）

1. **`gate-chinese-numeral` 漏掉了它自己的立案样本**：该 gate 为拦"亮三到五倍""不能低于九十"而建，收紧为"只在跟量词/单位时判违规"后，第二个样本不再被拦。实测 MISS：`不能低于九十`（立案样本本身，4 跑逐字出现全部通过）／`九十以上…`／`七十多厘米`（数词+多+单位，**泄的是 GB/T 50034 的 0.75m 参考平面＝定位数字进客户正文**）／`占去近半`／`这三项`／`二十几万`；误报 HIT：`这两点你要盯住`。建议：量词表补 `项|半|次|遍`，加"数词+多/几/来/余+单位"与"数词后接比较词（低于/高于/达到/不足）"两条形态。
2. **`check_type` 被 gate 完全忽略，`regex_require_annotation` 被当成 deny 执行**：实现是"凡带 pattern 的 check 一律 `if re.search: 违规`"，而 `cr-unit-translation` 声明的是"出现工程量纲**则要求**配翻译"——**语义反了**。当前因裸数字已禁而不会命中，是休眠 bug；一旦对渲染后文本回检或 release 新增 require 类判据即错拦。
3. **budget 域的纪律判据在成文线上没有承载体**：`cr-budget-disclaimer`(presence_require)/`cr-budget-no-commerce`(field_deny)/`cr-budget-range-width`/`cr-budget-stale-price` 全部无 pattern，gate 一条都不执行；`Card` 模型也没有可挂免责文案的字段。结果 r12 那张 **verdict=ok 的造价卡片没有挂 DISCLAIM_PRICE**，规则 5.15"必挂"在成文线上零拦截。
4. **可补的确定性降档洞**：`gate-thesis-degraded-anchor` 只扫主旨句里的 `{lkp-*}` 占位；主旨句不带占位、把降档结论用自然语言写出来完全绕过。规范 4.10c 已明说语义识别归判官层，但"**number_refs 含降档落点 且 assertions 为空 且 主旨句无占位**"这个组合可确定性检出，可作低误伤补充 gate。
