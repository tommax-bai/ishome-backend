## 一、这条裁决改掉的题目

上一版把"边界说法"交给句子、"单位"留给渲染层，结果单位违规 0/12 → 2/6。机制不是模型退步：
**`不超过三种` 在中文里是一个词组**，让它写前半、后半仍归代码，它顺手把整句写完了。
**所有权的线划在了一个词组中间，接缝处必漏。**

裁决把线挪到词组外面：单位也归句子，但**不是让模型自己想一个**——单位逐字预制在下发行里
（`你写：…不超过 {lkp-cct-variety-max} 种。`），模型照抄，机检逐字比对这条落点的 `unit`。
**单位仍由数据决定，写手只是搬运**，抄错、漏抄、抄成别条的单位当场就拦。

## 二、连带逼出来的一个更早的洞

单位既然要写进正文，数据里就不能放"要求写、写了就违规"的单位。扫一遍六域，两处撞：

- **lighting** `×环境照度` 含本域禁词「照度」——**而它已经逐字印在出过的成品里**（`亮出 3–5 ×环境照度`）；
- **storage** `延米` / `延米/㎡`，而「延米」本身就是该域禁词。

这不是新问题，是本轮才看见的老洞：**禁词检查跑在替换之前的文本上**，渲染层再把数据里的词面
替进去——禁词可以从数据侧绕过机检上纸。渲染层不认识禁词表，册级检查看不到渲染结果，
**唯一堵得住的地方是生产侧**：新增 `gate-unit-collides-banned-term`，整包拦下并说"改源"。

处置：lighting 改源 `×环境照度` → `倍`（题名 重点照明照度倍数 已说清相对什么），发 `lighting@v12`。
**storage 的「延米」未改**——延米既是真单位又是该域禁词，换成什么是产品措辞判断，且该域从未跑过；
守卫会在它第一次跑时响亮拦下并指名要改的东西。

## 四、同批重排了落点下发行

用户原话："这句话写的有问题…信息很杂很乱。" 原来一行挤了八种性质的东西，而且前半行给的四样里
有三样随后都要求它别写（内部编号、题名、单位、原始 JSON）。现形态四行封顶：

```
- 全屋色温种类上限｜没有外部依据，用「我们建议…」的口吻
  你写：…不超过 {lkp-cct-variety-max} 种。
  读者看到：…不超过 3 种。
  这是个上限，也可以用：最多／不多于
  （题名里的「上限」是内部标签，照抄未必对，按上面写）
```

**"你写"与"读者看到"并排的用处不止是好读**：单位该不该写、写在哪儿，一对照就看见了——
那句"别写单位"的叮嘱因此可以整句删掉，而它讲了两版都没拦住。

代价认下：本仓因此要拼一次"数+单位"，与渲染层同一条规则写在两处（坑单第 10 条同型，已在码内注明）。
