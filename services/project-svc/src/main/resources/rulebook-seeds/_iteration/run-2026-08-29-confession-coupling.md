## 二、耦合边界：三次措辞迭代才立住（每次都是真跑打的脸）

| 迭代 | 措辞 | 真跑结果 |
|---|---|---|
| 1 | 抽象禁令"不是它们之间有因果"+ 例句"两个尺寸只是恰好都关于床" | **归组塌了**：22~23 主张≈一落点一主张——例句把"不许编耦合"教成了"同属一件家具也不算一件事" |
| 2 | 改口"就该进同一条主张"+ 反例词面「得一起定」写进 prompt | **照抄禁句**：4/5 主张逐字带「得一起定」——与示范句可抄性同病，模型不区分句子挂的是对钩还是叉 |
| 3 | 词面撤出 prompt → `COUPLING_PHRASES` 确定性校验（词表逐字来自真跑），prompt 只留抽象规则 | **立住**：7 主张按**动作族**归组（床／站姿操作台／坐姿动作），耦合词零命中 |

沉淀出的一条一般规律（进坑单）：**禁止词面永远不进 prompt，进确定性校验**——prompt 里的任何
具体句子（示范也好反例也好）都会被抄。

## 三、假坦白：坦白之门刚开，隐藏档就想从这儿还魂（最要紧的新形态）

迭代 3 那次过检的 7 张卡里，两张是**假坦白**：

> `玄关柜深度、主通道宽度、次通道宽度、平开门衣柜前净距、电视观看距离这五项目前给不出可靠数值。`
> `冰箱散热净距目前给不出可靠数值。`

核对数据包：**七个落点全部有值**（`lkp-entry-cabinet-depth {min:350}`、`lkp-tv-distance
{min:1800,max:2400}`、`lkp-fridge-vent {min:50}`…），真缺口只有 `lkp-budget-driver` 一条。
即：未过门（REFERENCE_ONLY）的值被以"给不出"为名整批藏掉——**v2.4 禁止的隐藏行为借坦白语域
还魂**。三层封堵（reportgen `d87113b`）：

- 两步 prompt：坦白只许用于无背书**题目**与真缺口清单；有值的落点必须照发，值多软都要照讲；
- **gate-number-ref-unused**：这两张卡 number_refs 声明了五个落点、正文零占位符——契约原文
  "number_refs=占位符全集声明"，原先只查"用了没声明"，对称的另一半漏着，假坦白恰从这缝过检；
- **判官在观察层逮住了它**：`cr-undeclared-assertion` 命中 `厨房工作三角周长目前给不出可靠数值。`，
  理由"以断言口吻否定数值可靠性，但 lkp-work-triangle 是已声明的落点对象"——判官层价值的又一次实证
  （上一次是编标准号被三道核实拦下，这一次是它替结构门禁看住了语义面）。
