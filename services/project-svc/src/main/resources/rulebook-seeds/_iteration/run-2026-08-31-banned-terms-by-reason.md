# 真跑存档 · 2026-08-31 凌晨 · 禁词按「为什么禁」分组：出册 5/6，重写轮数减半

> 用户裁决：**"OK，增加上分类吧。"**

## 一、这件事不是"要去分类"

分类**本来就写在种子里**——`_common/banned-terms.yaml` 四组：

```yaml
weak:           ["可能", "建议考虑", "也许", "宜", "尽量", "视情况"]
methodology:    ["依据", "推导", "验收标准", "本方案", "经严谨", "综合考量", "作业范围"]
overreach:      ["保证", "确保效果", "一定不会", "承诺", "无风险"]
responsibility: ["责任", "免责", "由业主自行承担"]
```

导入脚本按类别各建一个 vocabulary 资产，分组一路进了库，**只在装包那一步被拍平**成一个按拼音
排序的平表。成文线拿到的是 25 个词、一句话："禁词（一个都不能出现）"，打回也只有一句"换人话说"。

**那句话对「照度」成立，对「可能」是错的指令。** 软话不是换个近义词能救的：换「或许」还是禁词，
换「大概」不在表里但立刻被弱词判据打。真跑 v5 就是这么烧掉两轮重写的——同一个「宜」，
禁词判据与弱词判据一起中同一句。

## 二、形态（五条，缺一条就不成立）

1. **包里加分组字段，平表不删**——扫描与守卫要平表，平表恒为分组的并集；
2. **prompt 按组分行**，每行给这一类的改法；
3. **打回按组给路，与 prompt 共用同一份路由表**——两处分家正是本轮在修的那类毛病；
4. **组名不认得就退回通用那句**——加组不破消费，新域新组不必改代码；
5. **路里不给替代词**——判据只判不写那条裁决的直接延续。替代说法固定进数据＝人预设模板。

灯光域四个工程词的组名由 `domain_extra` 改为 `jargon`（`lighting@v13`），拿到"换业主读得懂的
说法"那条路。**其余五域不动**——同「延米」那条先例：没跑过的域不预先分类。

## 三、第二个（更大的）用处：泛化

平表只禁**表上这些字符串**。带理由的分行能让模型避开**表上没有的近邻**：「大概」不在表里但同样
是软话；当初那个叠字缺陷的「不能多于」也是这样漏的（表里列了「不超过」）。
**告诉它这类词为什么不行，比多列几个词管用。**

## 四、路上捡到的四个洞

**① 我自己重犯了一次。** 第一版路由话写了「承诺」「责任」——**prompt 自己写禁词**，正是前一轮
在修的那个毛病，由新代码重演。成因是守卫测试当时只跑平表回退那条路，没盖住分组这条。
两处都修，守卫经**反证**有效（退回旧路由话即报错）。

**② 核验脚本两处漏读禁词**（都经反证）：跨域表按类别列在**顶层**，原先读 `items` 恒取到空——
**那 21 个公共禁词从没进过核验集**；persona 侧原先只读 `domain_extra` 一个键，而成文线读的是
全部列表值。两处都让"单位撞禁词"那道守卫漏拦。

**③ 纪律 3/5 分工不清，造成一次回归。** 上一轮把语域档改成"「可作支点」的可以拿来下判断"，
六跑里三跑出现模型**把落点题名当断言题目声明**（`gate-assertion-not-budgeted`，此前 18 跑一次
未现）。现形态：纪律 3 只管口吻、明说"下判断看第 5 条那张题目表"；纪律 5 写明"题目名与落点题名
是两张表"。连带：该判据的打回名单改为与纪律 5 **同一份**——原先列预算全集，模型照它挑一个没背书
的，下一轮撞另一条判据。

**④ 生产侧加字段把出册顶掉了。** 渲染层 `extra="forbid"`，顶层少声明一个字段整包解析失败——
两跑**成文已经过了**、死在出册这一步。渲染层照 `triggered_rules_by_domain` 那条先例
"声明它但不渲它"。**这已经是同一形态被真跑逮到的第二次**，回归钉住。
